## 漏洞详情

### 🚨 P0-001: ReDoS（正则表达式拒绝服务）攻击

**CVSS 评分**: 7.5 (High)  
**影响组件**: `background.js`, `shared.js`  
**漏洞类型**: CWE-400 (Uncontrolled Resource Consumption)

#### 漏洞描述

用户提供的 URL 模式直接插入 `RegExp` 构造函数，未做任何验证。攻击者可通过备份文件注入恶意正则表达式，导致浏览器在访问任何 URL 时卡死。

#### 漏洞代码

**background.js:67-72 (修复前)**
```javascript
const pattern = rule.urlPattern
  .replace(/\./g, '\\.')
  .replace(/\*/g, '.*');
try {
  if (!new RegExp(`^${pattern}$`).test(url)) continue;
} catch {
  continue;
}
```

#### 攻击场景

1. 攻击者构造恶意备份文件，包含如下规则：
```json
{
  "version": 1,
  "rules": [{
    "id": "evil",
    "urlPattern": ".*.*.*.*.*.*.*.*.*.*.*.*.*",
    "actions": [],
    "enabled": true
  }]
}
```

2. 用户导入该备份
3. 用户访问任何网页
4. 浏览器卡死（灾难性回溯）

#### 修复方案

**background.js (修复后)**
```javascript
// 验证 URL 模式的安全性
function validateUrlPattern(pattern) {
  if (typeof pattern !== 'string') 
    return { valid: false, error: 'Pattern must be a string' };
  
  if (pattern.length > 200) 
    return { valid: false, error: 'Pattern too long (max 200 chars)' };
  
  // 限制 * 数量
  const starCount = (pattern.match(/\*/g) || []).length;
  if (starCount > 10) 
    return { valid: false, error: 'Too many wildcards (max 10)' };
  
  // 检查是否有危险的正则字符
  const dangerousChars = /[+{}()|[^$\\\]/;
  if (dangerousChars.test(pattern.replace(/\*/g, '').replace(/\?/g, ''))) {
    return { valid: false, error: 'Pattern contains unsupported regex characters' };
  }
  
  return { valid: true };
}

// 安全的通配符匹配
function safeMatchPattern(pattern, url) {
  const validation = validateUrlPattern(pattern);
  if (!validation.valid) {
    console.warn('Invalid URL pattern:', pattern, validation.error);
    return false;
  }
  
  try {
    const escaped = pattern
      .replace(/[.+?^${}()|[\]\\]/g, '\\$&')
      .replace(/\*/g, '.*')
      .replace(/\?/g, '.');
    
    const regex = new RegExp(`^${escaped}$`);
    return regex.test(url);
  } catch (e) {
    console.warn('Regex creation failed for pattern:', pattern, e);
    return false;
  }
}
```

#### 修复验证

- ✅ 模式长度限制：200 字符
- ✅ 通配符数量限制：最多 10 个
- ✅ 危险字符检测：拒绝 `+{}()|[^$\\` 等正则特殊字符
- ✅ 安全的正则转义：使用 `\\$&` 转义
- ✅ 错误处理：捕获所有异常，记录警告日志

### 🚨 P0-002: 自定义 URL 验证缺失

**CVSS 评分**: 6.5 (Medium)  
**影响组件**: `popup.js`  
**漏洞类型**: CWE-20 (Improper Input Validation)

#### 漏洞描述

自定义商店 URL 未验证，用户可能被诱导输入 `javascript:alert(1)` 或 `data:text/html,<script>alert(1)</script>` 等危险 URL。点击"商店"按钮时会打开该 URL，导致脚本执行。

#### 漏洞代码

**popup.js:106-111 (修复前)**
```javascript
document.getElementById('customStoreUrl').onchange = async (e) => {
  storageData.browserConfig.customUrl = e.target.value.trim();
  await setStorage({ browserConfig: storageData.browserConfig });
};
```

#### 攻击场景

1. 用户打开扩展设置
2. 选择"自定义"浏览器类型
3. 输入 `javascript:alert(document.cookie)`
4. 点击"商店"按钮
5. 恶意脚本执行，窃取敏感信息

#### 修复方案

**popup.js (修复后)**
```javascript
// 自定义商店 URL 验证
document.getElementById('customStoreUrl').onchange = async (e) => {
  const url = e.target.value.trim();
  
  // 清空时不验证
  if (!url) {
    storageData.browserConfig = storageData.browserConfig || { type: 'custom' };
    storageData.browserConfig.type = 'custom';
    storageData.browserConfig.customUrl = '';
    await setStorage({ browserConfig: storageData.browserConfig });
    return;
  }
  
  // 验证 URL 格式和协议
  try {
    const parsed = new URL(url);
    if (!['https:', 'http:'].includes(parsed.protocol)) {
      alert('仅支持 HTTP/HTTPS 协议');
      e.target.value = storageData.browserConfig?.customUrl || '';
      return;
    }
    
    // 检查是否为危险协议
    if (url.toLowerCase().startsWith('javascript:') || 
        url.toLowerCase().startsWith('data:')) {
      alert('不支持该协议');
      e.target.value = storageData.browserConfig?.customUrl || '';
      return;
    }
    
    storageData.browserConfig = storageData.browserConfig || { type: 'custom' };
    storageData.browserConfig.type = 'custom';
    storageData.browserConfig.customUrl = url;
    await setStorage({ browserConfig: storageData.browserConfig });
  } catch (err) {
    alert('无效的 URL：' + err.message);
    e.target.value = storageData.browserConfig?.customUrl || '';
  }
};
```

#### 修复验证

- ✅ 协议白名单：仅允许 `http:` 和 `https:`
- ✅ 危险协议检测：拒绝 `javascript:` 和 `data:`
- ✅ URL 格式验证：使用 `new URL()` 解析
- ✅ 错误恢复：验证失败时恢复到之前的值
- ✅ 用户提示：友好的错误消息

### ⚠️ P1-001: 备份文件缺乏数据验证

**CVSS 评分**: 5.5 (Medium)  
**影响组件**: `popup.js`  
**漏洞类型**: CWE-20 (Improper Input Validation)

#### 漏洞描述

备份文件解析后直接使用，未验证数据结构。攻击者可通过构造恶意备份文件注入非法规则或分组，破坏扩展功能或导致异常行为。

#### 修复方案

**添加 `validateBackupData()` 函数**
```javascript
function validateBackupData(data) {
  if (!data || typeof data !== 'object') {
    return { valid: false, error: '无效的备份文件' };
  }
  
  if (data.version !== 1) {
    return { valid: false, error: '不支持的备份文件版本' };
  }
  
  // 验证 rules
  if (data.rules) {
    if (!Array.isArray(data.rules)) {
      return { valid: false, error: 'rules 必须是数组' };
    }
    
    for (const rule of data.rules) {
      // 验证规则结构
      if (typeof rule.id !== 'string') {
        return { valid: false, error: 'rule.id 必须是字符串' };
      }
      if (typeof rule.urlPattern !== 'string') {
        return { valid: false, error: 'rule.urlPattern 必须是字符串' };
      }
      if (!Array.isArray(rule.actions)) {
        return { valid: false, error: 'rule.actions 必须是数组' };
      }
      
      // 验证 URL 模式（复用 ReDoS 修复）
      const validation = validateUrlPattern(rule.urlPattern);
      if (!validation.valid) {
        return { valid: false, error: `规则 "${rule.urlPattern}" 无效: ${validation.error}` };
      }
      
      // 验证 actions
      for (const action of rule.actions) {
        if (typeof action.extId !== 'string') {
          return { valid: false, error: 'action.extId 必须是字符串' };
        }
        if (typeof action.enabled !== 'boolean') {
          return { valid: false, error: 'action.enabled 必须是布尔值' };
        }
      }
    }
  }
  
  // 验证 groups（类似逻辑）
  // ...
  
  return { valid: true };
}
```

#### 修复验证

- ✅ 数据结构验证：检查 `version`, `rules`, `groups` 的类型
- ✅ 规则验证：验证 `id`, `urlPattern`, `actions` 格式
- ✅ URL 模式验证：复用 `validateUrlPattern()`
- ✅ Action 验证：验证 `extId` 和 `enabled` 类型
- ✅ 分组验证：验证 `id`, `name`, `members` 格式

### ⚠️ P1-002: 缺少 Content Security Policy

**CVSS 评分**: 5.0 (Medium)  
**影响组件**: `manifest.json`  
**漏洞类型**: CWE-1021 (Improper Restriction of Rendered UI Layers)

#### 漏洞描述

未定义 CSP，攻击者可利用 XSS 漏洞执行恶意脚本。`manifest.json` 中缺少 `content_security_policy` 字段。

#### 修复方案

**manifest.json (修复后)**
```json
{
  "manifest_version": 3,
  "name": "__MSG_extName__",
  "description": "__MSG_extDesc__",
  "version": "1.0.1",
  "default_locale": "zh_CN",
  "icons": {
    "16": "icons/icon16.png",
    "48": "icons/icon48.png",
    "128": "icons/icon128.png"
  },
  "action": {
    "default_popup": "popup.html",
    "default_icon": {
      "16": "icons/icon16.png",
      "48": "icons/icon48.png"
    }
  },
  "background": {
    "service_worker": "background.js"
  },
  "permissions": [
    "management",
    "storage",
    "tabs"
  ],
  "host_permissions": [
    "<all_urls>"
  ],
  "web_accessible_resources": [
    {
      "resources": ["icons/*"],
      "matches": ["<all_urls>"]
    }
  ],
  "content_security_policy": {
    "extension_pages": "script-src 'self'; object-src 'self'; style-src 'self' 'unsafe-inline'"
  }
}
```

#### 修复验证

- ✅ `script-src 'self'`: 仅允许扩展自身的脚本
- ✅ `object-src 'self'`: 仅允许扩展自身的对象资源
- ✅ `style-src 'self' 'unsafe-inline'`: 允许内联样式（popup 需要）
- ✅ 版本号更新：`1.0.0` → `1.0.1`
